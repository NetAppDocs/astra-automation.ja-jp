= 名前空間を取得する
:allow-uri-read: 
:imagesdir: ../media/


[.api-doc-operation .api-doc-operation-get]#GET# [.api-doc-code-block]#`/accounts/{account_id}/topology/v1/namespaces/{namespace_id}`#

JSONレスポンスボディに格納されている名前空間APIリソースを返します。



[[parameters]]
== パラメータ

[cols="5*"]
|===
| Name | を入力します | 入力 | 必須 | 説明 


| account_id | string | path（パス） | True  a| 
包含するアカウントリソースのID

* 例：{{.Account}}




| namespace_id | string | path（パス） | True  a| 
リストする名前空間コレクションのID

|===


[[response]]
== 応答

[source]
----
Status: 200, Returns the stored Namespace API resource in the JSON response body.
----
[cols="4*"]
|===
| Name | を入力します | 必須 | 説明 


| を入力します | string | True  a| 
リソースのメディアタイプ。定義された値は次のとおりです：

* "application/astra-namespace"




| バージョン | string | True  a| 
リソースのバージョン。定義された値は次のとおりです：

* "1.0"
* "1.1"
* "1.2"




| ID | string | True  a| 
リソースのグローバル一意識別子。定義された値は次のとおりです：

* UUIDv4スキーマに準拠




| リンク | 配列[link:#type_astra_link["type_astra_link"]] | True  a| 
リソースに対してサポートされている操作を説明するリンク。



| 名前 | string | True  a| 
名前空間の名前を示す値を含むJSON文字列。定義された値は次のとおりです：

* 最小長さ：1
* 最大長さ：255




| namespaceState | string | True  a| 
名前空間の状態を示す値を含むJSON文字列。定義された値は次のとおりです：

* 「discovered」 - ネームスペースがクラスター内で検出されました
* 「削除済み」 - 名前空間がクラスターから削除されたか、クラスターが管理されていないが、名前空間を参照するリソースが存在する可能性がある




| namespaceStateDetails | 配列[link:#type_astra_stateDetail["type_astra_stateDetail"]] | True  a| 
「状態」が「状態 a」、「状態 b」、または「状態 c」に遷移した理由に関する詳細情報をリストした JSON オブジェクトの JSON 配列。詳細情報がない場合は、この配列は空になります。定義された値は次のとおりです：

* 最小アイテム数：0




| kubernetesLabels | 配列[link:#type_astra_label["type_astra_label"]] | False  a| 
JSONオブジェクトのJSON配列。各JSONオブジェクトには、名前空間に関連付けられたKubernetesラベルが含まれています。定義された値は次のとおりです：

* Kubernetesラベル配列スキーマに準拠




| kubernetesUID | string | True  a| 
名前空間リソースの Kubernetes 生成 UID を含む JSON 文字列



| clusterID | string | True  a| 
名前空間が含まれるクラスタのグローバルに一意な識別子を含むJSON文字列。定義済みの値は次のとおりです：

* Astra識別子スキーマに準拠




| systemType | string | False  a| 
名前空間がシステム名前空間の一種であることを示すJSON文字列。このフィールドは、システム名前空間の種類（存在する場合）を識別します（バージョン1.1のみ）。定義された値は次のとおりです：

* 「kubernetes」 - 一般的なKubernetes（K8s）システムの名前空間。例：「kube-system」
* 「netapp」 - NetAppシステムネームスペース。例：「trident」または「netapp-monitoring」
* "openshift" - OpenShiftシステム名前空間、例えば、"openshift-monitoring"
* 「rke」 - Rancherの名前空間。例：「cattle-logging」
* 「other」 - 他の場所に必ずしも当てはまらない一般的なシステムnamespace（例：「ingress-nginx」、「tekton-system」）




| メタデータ | link:#type_astra_metadata["type_astra_metadata"] | True  a| 
リソースに関連付けられた、クライアントおよびサービス指定のメタデータ。定義された値は次のとおりです：

* Astraメタデータスキーマに準拠
